`usewebmcp` registers React-owned tools with `document.modelContext`. Its browser contracts and JSON Schema input inference come from the Community Group's [`webmcp-types`](https://github.com/webmachinelearning/webmcp-types).

The runtime comes from the browser, [`@mcp-b/webmcp-polyfill`](/packages/webmcp-polyfill/overview), or [`@mcp-b/global`](/packages/global/overview). The hook does not install a runtime or MCP SDK. For MCP output metadata, prompts, resources, and clients, use [`@mcp-b/react-webmcp`](/packages/react-webmcp/reference).

## Installation

```bash title="Install packages"
pnpm add usewebmcp react
```

React 18 and 19 are supported. The published entry point preserves `'use client'`, including production builds. Importing and server rendering do not access browser globals or register tools. Framework integration is covered in the [framework guide](/how-to/frameworks).

## Hook

### `useWebMCP(config, deps?)`

`deps` is an optional React dependency list for explicitly refreshing registration.

| Returned field             | Type                          | Description                                             |
| -------------------------- | ----------------------------- | ------------------------------------------------------- |
| `state`                    | `ToolExecutionState<TResult>` | Execution state                                         |
| `execute(input, options?)` | `Promise<TResult>`            | Local execution with optional `{ signal }`              |
| `reset()`                  | `void`                        | Clears observed execution state without cancelling work |
| `isSupported`              | `boolean`                     | A registration API is available                         |
| `isRegistered`             | `boolean`                     | The current registration succeeded                      |
| `registrationError`        | `Error \| null`               | Metadata conversion or registration failure             |

## Config fields

| Field                     | Type                                                 | Required | Description                                     |
| ------------------------- | ---------------------------------------------------- | -------- | ----------------------------------------------- |
| `name`                    | `string`                                             | Yes      | Tool identifier                                 |
| `title`                   | `string`                                             | No       | Human-readable label                            |
| `description`             | `string`                                             | Yes      | Tool description                                |
| `inputSchema`             | JSON Schema or Standard JSON Schema v1               | No       | Input metadata and inference                    |
| `annotations`             | `WebMCP.ToolAnnotations`                             | No       | Upstream behavior hints                         |
| `execute(input, options)` | `(input, { signal }) => TResult \| Promise<TResult>` | Yes      | Validated tool implementation                   |
| `enabled`                 | `boolean`                                            | No       | Defaults to true; controls registration         |
| `exposedTo`               | `string[]`                                           | No       | Forwarded to the browser's registration options |
| `formatOutput`            | `(result: TResult) => unknown`                       | No       | Formats agent-facing results                    |

`enabled: false` unregisters the tool while leaving local execution available. The browser enforces origin exposure; see the [Community Group draft](https://webmachinelearning.github.io/webmcp/#dictdef-modelcontextregistertooloptions).

## Execution state

| Field            | Type              | Description                                |
| ---------------- | ----------------- | ------------------------------------------ |
| `isExecuting`    | `boolean`         | At least one execution is pending          |
| `lastResult`     | `TResult \| null` | Most recent successful result              |
| `error`          | `Error \| null`   | Most recent execution error                |
| `executionCount` | `number`          | Successful executions since the last reset |

The handler always receives an `AbortSignal`, including on older runtimes that omit execution options. Runtimes that omit the options bag receive a fresh signal; runtime cancellation can propagate only when the runtime forwards its signal. Local calls can provide their own signal. Cancellation rejects the call and clears its pending state. Work that ignores cancellation cannot replace state when it finishes later.

## Schemas and inference

<StandardSchemaExample />

Arguments `{ count: "2" }` become `{ count: 2, limit: 10 }` before the handler runs, producing `{ total: 12 }`.

Inline JSON Schema literals infer caller and handler inputs through upstream types. Reusable schemas retain literals with `as const`. `TResult` is inferred from the handler's return value.

[Standard JSON Schema v1](https://standardschema.dev/json-schema) supplies metadata through `~standard.jsonSchema.input()`, trying draft 2020-12 and then draft-07. When a schema also implements [Standard Schema v1](https://standardschema.dev/), every call runs `~standard.validate()` before the handler. Async validation is awaited. Callers supply the input type, while the handler receives the validated output type, including transforms and defaults.

The hook calls the schema library's methods; it does not bundle a validation engine. Standard JSON Schema conversion and Standard Schema validation are separate interfaces.

Validation errors reject local calls, produce agent error responses, and do not invoke the handler. JSON Schema objects and converter-only schemas supply metadata and inference without adding runtime validation. A validator-only schema must also provide a JSON Schema converter. The [schema guide](/how-to/use-schemas-and-structured-output) covers React and direct registration. The optional [polyfill schema entry](/packages/webmcp-polyfill/reference#schema-entry) converts metadata without wrapping execution; the hook owns validation on native, polyfilled, and MCP-B runtime paths.

## Re-registration triggers

Registration refreshes when serialized tool metadata, `enabled`, `exposedTo`, or explicit `deps` change. Equivalent inline metadata does not re-register a tool. The latest committed callback and validator apply without callback-reference-driven registration changes.

Committed callbacks are published with a layout effect in the browser and a passive effect on the server. Suspended or abandoned renders do not replace the active implementation. Cleanup aborts the component's registration signal.

When the API is absent, the hook checks every 500 ms for up to 10 seconds to detect late extension injection. It stops checking after discovery or unmount. `navigator.modelContext` remains a compatibility fallback. A registration that resolves or rejects after cleanup cannot change the replacement registration's state.

## Tool responses

Successful agent calls return the handler's value unless `formatOutput` is supplied. Local execution and `state.lastResult` retain the original result. Thrown or returned `Error` objects produce an agent response with `isError: true`; local calls reject.

`outputSchema`, MCP-specific annotations, and automatic text/`structuredContent` formatting belong to [`@mcp-b/react-webmcp`](/packages/react-webmcp/reference#usewebmcpconfig-deps). Existing users needing that behavior can change the import to that package.

## Exported types

| Type                                         | Description                                                  |
| -------------------------------------------- | ------------------------------------------------------------ |
| `WebMCP`                                     | Upstream namespace from `webmcp-types`                       |
| `WebMCPConfig<TInputSchema, TResult>`        | Configuration with the result type inferred from the handler |
| `WebMCPReturn<TInputSchema, TResult>`        | Execution and registration state and controls                |
| `ToolExecutionState<TResult>`                | Execution state                                              |
| `ToolExecuteFunction<TInputSchema, TResult>` | Handler signature                                            |
| `ToolInputSchema`                            | Accepted schema object                                       |
| `InferToolInput<TInputSchema>`               | Caller input before validation                               |
| `InferValidatedToolInput<TInputSchema>`      | Handler input after validation                               |

The second generic parameter of core configuration and return types is now the result type. The previous `InferOutput` helper and output-schema-based generics remain available from `@mcp-b/react-webmcp`.
