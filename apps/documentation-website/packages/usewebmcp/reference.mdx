`usewebmcp` registers React-owned tools with `document.modelContext`. Browser contracts and
JSON Schema inference come from the Community Group's [`webmcp-types`](https://github.com/webmachinelearning/webmcp-types).
Provide native WebMCP, the [polyfill](/packages/webmcp-polyfill/overview), or
[`@mcp-b/global`](/packages/global/overview). Importing the hook does not initialize the runtime.

## Installation

```bash title="Install the hook"
pnpm add usewebmcp react
```

React 18/19, SSR, and StrictMode are supported. The published entry preserves `'use client'`.
Server rendering does not register tools. See [framework setup](/how-to/frameworks).

## Hooks

### `useWebMCP(config, deps?)`

Registers a tool and returns the fields below. It neither allocates an execution store nor
subscribes to tool calls. `deps` optionally forces a registration refresh.

| Return                     | Type               | Meaning                                        |
| -------------------------- | ------------------ | ---------------------------------------------- |
| `execute(input, options?)` | `Promise<TResult>` | Local raw result; optional cancellation signal |
| `isSupported`              | `boolean`          | A registration API is available                |
| `registrationError`        | `Error \| null`    | Metadata conversion or registration failure    |

There is no `state`, `reset`, or `isRegistered` return. Use the runtime's `getTools()` for
confirmed discovery. Successful asynchronous registration adds no execution-state subscription.

### `useToolExecutionState(execution)`

Subscribes to a stable `executionState<TResult>()` plugin/store using `useSyncExternalStore`.
Attach that store through `plugins` to record calls. Subscribing does not attach the plugin,
reset the store, or cancel work. SSR and initial hydration use the idle snapshot.

<ExecutionStateExample />

The snapshot has `isExecuting`, `lastResult`, `error`, and `executionCount`.
`execution.reset()` clears observations without cancelling pending work.
The [plugin reference](https://github.com/WebMCP-org/npm-packages/tree/main/packages/webmcp-plugins#execution-state)
describes overlapping calls and subscriptions.

## Config fields

| Field                         | Meaning                                                         |
| ----------------------------- | --------------------------------------------------------------- |
| `name`, `description`         | Required browser tool metadata                                  |
| `execute(input, options)`     | Handler receiving validated input and `{ signal }`              |
| `inputSchema`                 | Optional JSON Schema or Standard JSON Schema implementation     |
| `annotations`                 | Browser tool hints                                              |
| `enabled`                     | Registers while `true`; defaults to `true`                      |
| `exposedTo`                   | Browser-enforced discovery/call origin metadata                 |
| `plugins`                     | Named `{ name, aroundInvoke }` objects, outermost first         |
| `binding(input)`              | Serializable approval description for non-JSON validated inputs |
| `checkBinding()`              | Recheck current authority immediately before execution          |
| `formatOutput`, `formatError` | Optional agent response formatters                              |
| `isErrorResponse`             | Protocol adapter response classifier                            |

Plugins come from [`@mcp-b/webmcp-plugins`](https://github.com/WebMCP-org/npm-packages/tree/main/packages/webmcp-plugins).
Standard Schema preparation runs once before consent. Put state and tracing before consent to
observe validation failures and approval waiting. React calls the latest committed `checkBinding`
while retaining the invocation's captured handler and prepared arguments.

### Re-registration triggers

Tool metadata, `enabled`, or explicit dependencies refresh registration.
Changing a handler or supplying an equivalent inline schema does not refresh it.
Handlers use the latest committed props; abandoned renders cannot replace them.
Schema conversion and serialization are cached by object identity. Replace a schema object when
its contents change. Include authority versions in `deps` when changes should revoke approval.

`enabled: false` unregisters the tool while local `execute()` remains available. Cleanup removes
only the registration owned by this hook. When no runtime is present at mount, the hook retries
every 500 ms for up to 10 seconds.

### Cancellation

The handler receives a combined call/registration signal. Agent work waiting for approval is
revoked when its registration changes or unmounts. Local calls retain their captured callback
and use the individual caller signal. Cancellation always rejects, including during asynchronous
validation or response formatting. Ignoring a signal cannot undo work that has already executed.

## Schemas and inference

<StandardSchemaExample />

`inputSchema` remains the React schema API. [Standard JSON Schema v1](https://standardschema.dev/json-schema)
provides metadata; [Standard Schema v1](https://standardschema.dev/) provides validation.
The hook selects the shared input adapter and awaits supplied validation, including transforms
and defaults. Caller types describe raw input; handler types describe validated output.

Plain JSON Schema and converter-only schemas provide metadata and inference without a runtime
validator. A validator-only schema must also provide JSON Schema conversion. No validation engine
is bundled. See the [schema guide](/how-to/use-schemas-and-structured-output) for direct callbacks.

## Tool responses

Core local and agent calls return raw values and reject failures by default. `formatOutput` and
`formatError` customize agent responses; async formatters are awaited. Local calls skip agent
formatting and preserve raw results/errors. Cancellation always rejects.

[`@mcp-b/react-webmcp`](/packages/react-webmcp/reference) adds MCP output schemas and automatic
text/`structuredContent` formatting. Protocol error classification belongs to that adapter.

## Migration

`useWebMCPTool` is removed; use the registration-only `useWebMCP`. The hook no longer returns
`state`, `reset`, or `isRegistered`. Add an `executionState()` plugin and explicitly subscribe
where state is displayed. Replace `middleware` with named `plugins`.

Invocation helpers and plugin factories now live in `@mcp-b/webmcp-plugins`; the old polyfill
entries are removed. `inputSchema: vendorSchema` remains supported. The
[package migration](https://github.com/WebMCP-org/npm-packages/tree/main/packages/webmcp-plugins#migration-from-the-polyfill-entries)
lists renamed factories.
