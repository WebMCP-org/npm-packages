`@mcp-b/webmcp-polyfill` bundles the upstream
[webmachinelearning/webmcp-polyfill](https://github.com/webmachinelearning/webmcp-polyfill)
at revision `439c6c341f1c632c63498ba206e2bd8471cb8efb`. It installs the
standard `document.modelContext` runtime when the browser does not provide one.
The [WebMCP draft](https://webmachinelearning.github.io/webmcp/) and upstream
package define the core API.

Use [`@mcp-b/global`](/packages/global/reference) for MCP-B runtime extensions,
including transports, prompts and resources, declarative forms, compatibility
shims, and MCP `outputSchema` support.

## Package entries

| Import                          | Purpose                                             |
| ------------------------------- | --------------------------------------------------- |
| `@mcp-b/webmcp-polyfill`        | ESM installer for the bundled upstream runtime      |
| `@mcp-b/webmcp-polyfill/iife`   | Script bundle that installs the runtime when loaded |
| `@mcp-b/webmcp-polyfill/schema` | MCP-B schema and response helpers                   |

The standalone bundle installs `document.modelContext` automatically:

```html "Load the polyfill"
<script src="https://unpkg.com/@mcp-b/webmcp-polyfill@latest/dist/index.iife.js"></script>
```

## `installWebMCP()`

Call the installer before registering tools:

```ts
import { installWebMCP } from '@mcp-b/webmcp-polyfill';

installWebMCP();
```

Installation is idempotent and preserves an existing native context. It does
nothing when the browser document is unavailable. Importing the ESM entry does
not install the runtime as a side effect.

`initializeWebMCPPolyfill()` remains as a deprecated alias:

```ts
import { initializeWebMCPPolyfill } from '@mcp-b/webmcp-polyfill';

initializeWebMCPPolyfill();
```

## Core runtime

The installed `document.modelContext` implementation comes from the pinned
upstream package. Use the upstream
[API reference](https://webmachinelearning.github.io/webmcp/) for method
signatures and behavior. The polyfill follows the current object-input
`executeTool()` shape and supports registration cancellation through
`AbortSignal`.

The core package does not provide:

- `cleanupWebMCPPolyfill()` or another uninstall operation.
- A `navigator.modelContext` alias or `navigator.modelContextTesting` shim.
- Declarative forms or `SubmitEvent` extensions.
- MCP `outputSchema` metadata.

These MCP-B extensions belong to [`@mcp-b/global`](/packages/global/reference).
The upstream context remains installed for the lifetime of its document.

## Schema entry

`@mcp-b/webmcp-polyfill/schema` remains available for MCP-B schema and response
helpers. It is separate from the upstream core runtime.

`normalizeInputSchema()` converts JSON Schema and
[Standard JSON Schema v1](https://standardschema.dev/json-schema)
implementations. Conversion calls `~standard.jsonSchema.input()`, trying
`draft-2020-12` and then `draft-07`. When a
[Standard Schema v1](https://standardschema.dev/) validator is also present, the
helper preserves `~standard.validate()` as a non-enumerable property for the MCP
SDK. It does not invoke the validator or wrap the tool callback.

| Registration/execution path                                | Schema conversion                                    | Argument validation                                              |
| ---------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------- |
| `usewebmcp` or the MCP-B tool hook                         | Automatic for Standard JSON Schema                   | Supplied Standard Schema validator on local and agent calls      |
| Core polyfill imperative API                               | Caller supplies JSON Schema                          | Caller validates in the handler                                  |
| `normalizeInputSchema()` helper                            | Converts metadata and preserves a supplied validator | None; this helper does not execute tools                         |
| `BrowserMcpServer` through an MCP client                   | Automatic conversion                                 | MCP server uses a preserved validator or its JSON Schema adapter |
| Direct `BrowserMcpServer.executeTool()` or a native mirror | Already converted metadata                           | Bypasses MCP validation; caller validates in the handler         |

The [schema guide](/how-to/use-schemas-and-structured-output) covers the
registration paths. When your callback owns validation,
`{ ...normalizeInputSchema(schema).inputSchema }` copies only JSON metadata.
This prevents the MCP SDK from applying vendor transforms a second time if the
tool later uses the MCP-B runtime.

The schema entry exports these helper groups:

| Group               | Exports                                                                                                                                      |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Schema types        | `ToolInputSchema`, `NormalizedInputSchema`                                                                                                   |
| Schema conversion   | `normalizeInputSchema`, `serializeInputSchema`                                                                                               |
| Descriptor handling | `coerceWebMcpToolDescriptor`, `validateWebMcpToolDescriptor`, `normalizeToolResponse`, `toWebMcpAnnotations`                                 |
| Chrome wire format  | `parseChromeToolInput`, `serializeChromeToolResult`                                                                                          |
| Access and aborts   | `validatePotentiallyTrustworthyOrigins`, `validateExecutableOrigin`, `validateWebMcpAccess`, `validateOriginAgentCluster`, `withAbortSignal` |
| Error construction  | `createUnknownError`, `createToolInvocationFailedError`, `createInvalidStateError`                                                           |
| Object detection    | `isPlainObject`                                                                                                                              |

The `document.modelContext.registerTool()` boundary does not convert schema
metadata or validate invocation arguments. It follows WebMCP. Use
`@mcp-b/global` when you need MCP-side validation, structured responses, or
`outputSchema` metadata.
