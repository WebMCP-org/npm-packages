<Warning>
  `@mcp-b/webmcp-polyfill` is deprecated. For the standard imperative API, install the W3C Community
  Group polyfill, [`@w3c/webmcp-polyfill`](https://github.com/w3c-oss/webmcp-polyfill).
</Warning>

`@mcp-b/webmcp-polyfill` passes through to [`@w3c/webmcp-polyfill`](https://github.com/w3c-oss/webmcp-polyfill), which installs the standard `document.modelContext` surface when the browser does not provide one. It adds one thing: a temporary MCP-B layer for declarative tools and their `SubmitEvent` extensions, kept until the official polyfill ships them. Existing browser contexts and native `SubmitEvent` hooks are preserved; missing hooks are filled in.

## When to use this package

- You need declarative tools in browsers without native support and do not want the full [`@mcp-b/global`](/packages/global/overview) runtime.

## When not to use this package

- You only use the imperative API (`registerTool`, `getTools`, `executeTool`). Use [`@w3c/webmcp-polyfill`](https://github.com/w3c-oss/webmcp-polyfill).
- You need prompts, resources, browser transport, or direct access to an MCP server. Use [`@mcp-b/global`](/packages/global/overview).
- You only need types at build time. Install [`webmcp-types`](https://github.com/webmachinelearning/webmcp-types), the package Chrome's [Imperative API guide](https://developer.chrome.com/docs/ai/webmcp/imperative-api) recommends.

## Where it sits in the package graph

This package depends on `@w3c/webmcp-polyfill` as a normal npm dependency and adds the declarative layer on top. [`@mcp-b/global`](/packages/global/overview) wraps it when MCP-B extensions are needed.

## First step

Initialize the polyfill before your app registers tools. The [reference page](/packages/webmcp-polyfill/reference) documents the installer and the temporary declarative layer. For prompts, resources, transports, or MCP `outputSchema`, use the [global runtime](/packages/global/reference).
