## Package boundary

Tool lifecycle, execution state, cancellation, and Standard Schema validation come from
[`usewebmcp`](/packages/usewebmcp/overview). This package adds `outputSchema`, MCP annotations,
automatic MCP formatting, context tools, prompt/resource hooks, and an MCP client provider.
Both packages support React 18/19 and preserve `'use client'`.

Choose `usewebmcp` when you want browser tools with raw results. Choose this package for any of the
MCP features above. Both call the validator supplied by your input schema; see the
[schema guide](/how-to/use-schemas-and-structured-output).

The [React commit comparison](/packages/usewebmcp/overview#react-updates-measured) measures
both tool hooks against MCP Cat and Google's hooks. The
[full results and feature table](https://github.com/WebMCP-org/npm-packages/tree/b45d1e9e2e51b0b49f959b02960e37002d0a65bf/benchmarks/react-hooks)
explain the scenarios and API differences.

## Runtime requirements

| Surface                       | Runtime                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------- |
| Tool and context hooks        | Native WebMCP, an initialized polyfill, or the MCP-B runtime                    |
| Prompt and resource hooks     | [`@mcp-b/global`](/packages/global/overview) or a configured `BrowserMcpServer` |
| MCP client provider and hooks | A supplied MCP client and transport; no browser registry required               |

MCP `outputSchema` discovery and protocol validation require the MCP-B runtime. Native WebMCP and
the standalone polyfill do not advertise this metadata. The [reference](/packages/react-webmcp/reference)
describes each hook and the [boundary explanation](/explanation/strict-core-vs-mcp-b-extensions)
connects the browser and MCP layers.
