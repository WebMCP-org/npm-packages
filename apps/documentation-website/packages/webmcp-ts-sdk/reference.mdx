`@mcp-b/webmcp-ts-sdk` provides `BrowserMcpServer`, a composition adapter over the official MCP TypeScript SDK v2. The adapter translates the WebMCP browser surface to an internal v2 `McpServer`; it does not subclass or fork that server.

```bash "Terminal"
pnpm add @mcp-b/webmcp-ts-sdk @mcp-b/transports
```

<Note>
  Most applications should use [`@mcp-b/global`](/packages/global/overview). It creates, connects,
  and installs a `BrowserMcpServer` on `document.modelContext`.
</Note>

## Responsibility boundary

| Layer                 | Responsibilities                                                                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MCP TypeScript SDK v2 | Dynamic MCP registrations, protocol handling, transport lifecycle, list-change notifications, Standard Schema, Zod 4.2+, and raw JSON Schema through `fromJsonSchema` |
| `BrowserMcpServer`    | WebMCP descriptor registration, `document.modelContext` events, native Chrome mirroring and backfill, plus MCP-B prompt, resource, sampling, and elicitation helpers  |

Use the official [`@modelcontextprotocol/server`](https://ts.sdk.modelcontextprotocol.io/v2/api/%40modelcontextprotocol/server/) directly when no browser adapter is required.

## `BrowserMcpServer`

### Constructor

```ts "constructor.ts"
new BrowserMcpServer(serverInfo: Implementation, options?: BrowserMcpServerOptions)
```

`BrowserMcpServerOptions` extends the upstream v2 `ServerOptions` and adds one property:

| Property | Type                | Description                                                                     |
| -------- | ------------------- | ------------------------------------------------------------------------------- |
| `native` | `ModelContextCore?` | Existing native or polyfilled context that receives mirrored tool registrations |

The adapter forwards upstream options, including `capabilities` and `jsonSchemaValidator`, to the composed `McpServer`. It always enables list-change support for tools, resources, and prompts.

```ts "native-adapter.ts"
import { BrowserMcpServer } from '@mcp-b/webmcp-ts-sdk';

const server = new BrowserMcpServer(
  { name: 'catalog-app', version: '1.0.0' },
  { native: document.modelContext }
);

const added = await server.syncNativeTools();
```

### `server`

```ts "server-property.ts"
readonly server: McpServer['server']
```

The low-level upstream server used for MCP client requests such as sampling and elicitation.

## WebMCP tool methods

The authoritative browser API is the [WebMCP specification](https://webmachinelearning.github.io/webmcp/). `BrowserMcpServer` implements its tool registration, discovery, and event shape while retaining MCP-B extensions.

### `registerTool(tool, options?)`

```ts "register-tool-signature.ts"
registerTool(
  tool: ToolDescriptor,
  options?: ModelContextRegisterToolOptions
): Promise<void>
```

Registers a WebMCP descriptor and creates the corresponding upstream v2 registration.

| Option      | Type           | Description                                                            |
| ----------- | -------------- | ---------------------------------------------------------------------- |
| `signal`    | `AbortSignal?` | Removes the MCP registration and native mirror when aborted            |
| `exposedTo` | `string[]?`    | Forwards cross-document exposure origins to the native browser context |

The native mirror receives the current WebMCP fields, including `title`, `readOnlyHint`, and `untrustedContentHint`. MCP-only `outputSchema` and annotations remain on the MCP registration.

```ts "register-tool.ts"
const controller = new AbortController();

await server.registerTool(
  {
    name: 'search',
    description: 'Search products',
    inputSchema: {
      type: 'object',
      properties: {
        query: { type: 'string' },
      },
      required: ['query'],
      additionalProperties: false,
    },
    async execute({ query }) {
      return {
        content: [{ type: 'text', text: `Found: ${String(query)}` }],
      };
    },
  },
  {
    signal: controller.signal,
    exposedTo: ['https://checkout.example'],
  }
);

controller.abort();
```

The adapter:

1. Normalizes the WebMCP JSON Schema.
2. Registers the tool on the composed v2 `McpServer`.
3. Mirrors the descriptor to `native.registerTool()` when `native` is set.
4. Queues a `toolchange` event.

A pre-aborted signal rejects with `signal.reason`. Duplicate or invalid names
reject the returned promise. If native Chrome blocks mirroring through
Permissions Policy, registration rejects and the local MCP registration rolls
back.

### `getTools(options?)`

```ts "get-tools-signature.ts"
getTools(options?: ModelContextGetToolOptions): Promise<RegisteredTool[]>
```

Returns browser tool metadata for the adapter's registry. Each item contains the serialized input schema, current origin, and current window. The method accepts the current `fromOrigins` option shape; the adapter reports its local registry and leaves cross-document filtering to the native browser.

### `ontoolchange` and `EventTarget`

`BrowserMcpServer` provides `ontoolchange`, `addEventListener`, `removeEventListener`, and
`dispatchEvent`. Local registrations and removals queue a `toolchange` task. Native runtimes own
cross-document delivery and ordering.

```ts "toolchange.ts"
server.addEventListener('toolchange', () => {
  console.log('Tool registry changed');
});
```

### `executeTool(tool, inputArgsJson, options?)`

```ts "execute-tool-signature.ts"
executeTool(
  tool: RegisteredTool,
  inputArgsJson: string,
  options?: ChromeModelContextExecuteToolOptions
): Promise<string | null>
```

Executes a descriptor returned by `getTools()`. This method follows the optional extension in [Chrome's imperative API](https://developer.chrome.com/docs/ai/webmcp/imperative-api); it is not part of the strict WebMCP core. The optional signal interrupts the returned promise.

### `unregisterTool(nameOrTool)` (deprecated)

Removes a tool for older MCP-B integrations. New code must pass a signal to `registerTool()` and abort it.

## MCP-B tool extensions

These methods are outside the WebMCP standard:

| Method                          | Return type       | Description                                              |
| ------------------------------- | ----------------- | -------------------------------------------------------- |
| `listTools()`                   | `ToolListItem[]`  | Lists MCP-B tool metadata, including `outputSchema`      |
| `backfillTools(tools, execute)` | `number`          | Adds descriptors supplied by a compatibility runtime     |
| `syncNativeTools()`             | `Promise<number>` | Reconciles and watches the configured native tool source |

`await server.syncNativeTools()` performs the initial reconciliation and returns the number of native tools added to the MCP registry. It subscribes to native `toolchange` events, adding new tools and removing previously backfilled tools that are no longer exposed. Synchronization uses `getTools()` plus Chrome's optional `executeTool()`.

Use Chrome's [Model Context Tool Inspector](https://chromewebstore.google.com/detail/model-context-tool-inspec/gbpdfapgefenggkahomfgkhfehlcenpd) to inspect mirrored tools.

## Schema handling

The browser-facing `inputSchema` is JSON Schema-first. The adapter normalizes it to MCP v2's
`StandardSchemaWithJSON` contract. Plain JSON Schema is wrapped with the
official `fromJsonSchema` helper; Standard Schema inputs retain their validator,
refinements, and transforms. The official v2 server owns MCP-call validation.

WebMCP accepts array-root input schemas because arrays are JavaScript objects. MCP requires tool
input schemas to have an object root. The adapter keeps such tools available through WebMCP, omits
them from the MCP tool list, and logs a warning rather than breaking `tools/list`.

The official v2 server owns Standard Schema conversion and validation for direct MCP registrations:

- Zod 4.2 or newer works through Standard Schema.
- Other Standard Schema implementations can be used when they expose JSON Schema conversion.
- Raw JSON Schema can be wrapped with `fromJsonSchema` in direct upstream registrations.
- Zod 3 is unsupported.

```ts "upstream-server.ts"
import { fromJsonSchema, McpServer } from '@modelcontextprotocol/server';

const mcpServer = new McpServer({ name: 'catalog-api', version: '1.0.0' });

mcpServer.registerTool(
  'lookup-product',
  {
    inputSchema: fromJsonSchema<{ sku: string }>({
      type: 'object',
      properties: { sku: { type: 'string' } },
      required: ['sku'],
    }),
  },
  async ({ sku }) => ({
    content: [{ type: 'text', text: `Looking up ${sku}` }],
  })
);
```

See the upstream [schema library guide](https://ts.sdk.modelcontextprotocol.io/v2/advanced/schema-libraries) and [v2 migration guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/upgrade-to-v2).

## Resources

### `registerResource(descriptor)`

Registers an MCP resource through the v2 server and stores its MCP-B descriptor. Returns `{ unregister(): void }`.

```ts "resource.ts"
const registration = server.registerResource({
  uri: 'app://settings',
  name: 'App settings',
  mimeType: 'application/json',
  async read(uri) {
    return {
      contents: [{ uri: uri.href, text: JSON.stringify({ theme: 'system' }) }],
    };
  },
});

registration.unregister();
```

`listResources()` returns descriptor metadata. `readResource(uri)` reads the registered URI and throws when it is missing.

## Prompts

### `registerPrompt(descriptor)`

Registers an MCP prompt through the v2 server and stores its MCP-B descriptor. Returns `{ unregister(): void }`.

```ts "prompt.ts"
const registration = server.registerPrompt({
  name: 'summarize',
  description: 'Summarize a document',
  argsSchema: {
    type: 'object',
    properties: {
      url: { type: 'string' },
    },
    required: ['url'],
  },
  async get(args) {
    return {
      messages: [
        {
          role: 'user',
          content: { type: 'text', text: `Summarize ${String(args.url)}` },
        },
      ],
    };
  },
});

registration.unregister();
```

`listPrompts()` returns prompt metadata. `getPrompt(name, args?)` validates arguments and invokes the descriptor.

## Sampling and elicitation

| Method                            | Description                                                 |
| --------------------------------- | ----------------------------------------------------------- |
| `createMessage(params, options?)` | Forwards an MCP sampling request to the connected client    |
| `elicitInput(params, options?)`   | Forwards an MCP elicitation request to the connected client |

Both methods apply a 10-second timeout when the caller does not supply an abort signal.

## Transport lifecycle

### `connect(transport)`

Connects the composed v2 `McpServer` to an MCP `Transport`.

<Note>
  `BrowserMcpServer.connect(customTransport)` uses SDK v2's legacy 2025-era route. Installing v2
  does not make `TabServerTransport`, iframe transports, or other custom transports speak MCP
  2026-07-28. Instance-level sampling and elicitation helpers are legacy-only and throw on
  modern-era v2 instances. See [Supporting protocol revision
  2026-07-28](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28).
</Note>

```ts "transport.ts"
import { TabServerTransport } from '@mcp-b/transports';

await server.connect(
  new TabServerTransport({
    allowedOrigins: ['https://shop.example'],
  })
);
```

### `close()`

Aborts native mirrors, clears their cleanup handles, and closes the composed MCP server.

| [`@modelcontextprotocol/client`](https://ts.sdk.modelcontextprotocol.io/v2/api/%40modelcontextprotocol/client/) | `Client`                                                               |

`McpServer` is the upstream v2 class. It is not an alias for `BrowserMcpServer`. New MCP-only code should import from the official split package that owns each symbol.
