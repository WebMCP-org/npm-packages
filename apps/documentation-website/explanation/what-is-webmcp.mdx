WebMCP proposes browser APIs for publishing structured tools. JavaScript uses
`document.modelContext`, while the declarative proposal lets HTML forms describe
tools without replacing their visible controls or validation.

These tools run inside the document's origin, authenticated session,
application state, and event loop. Unlike a remote MCP server, a WebMCP tool can
operate on the page the user is currently viewing and remain tied to that
document's lifecycle.

That location is the point of the design. Agents get an explicit capability
contract from the site instead of inferring intent from screenshots, DOM shape,
or brittle automation scripts.

The [WebMCP Community Group draft](https://webmachinelearning.github.io/webmcp/)
is authoritative for the proposed standard surface. Chrome currently exposes
an experimental implementation. MCP-B supplies implementation and integration
tooling, including the strict polyfill, React bindings, browser transports,
iframe bridges, and local relays. MCP-B capabilities beyond the standard tool
surface are extensions.

For implementation, follow [Build your first tool](/tutorials/first-tool) and
[Choose a runtime](/how-to/choose-runtime).
