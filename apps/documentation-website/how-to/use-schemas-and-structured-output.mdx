Use your schema library to validate tool arguments and transform them before your handler runs.
The [schema boundary explanation](/explanation/strict-core-vs-mcp-b-extensions#why-standard-schema-support-lives-in-the-adapters) describes how browser metadata and validation relate.

## Validate React tool input

Install the hook and the schema library used in this example:

```bash title="Install the hook and Zod"
pnpm add usewebmcp zod@^4.2
```

Provide a runtime as described in the [framework guide](/how-to/frameworks). Pass the complete
schema as `inputSchema`:

<StandardSchemaExample />

Call `useTotalTool()` in your component. An agent call with `{ count: "2" }`, or a local
`tool.execute({ count: "2" })`, returns `{ total: 12 }`. The handler receives the number `2` and
the default limit `10`. Invalid input fails before execution; async validation is awaited.

Use the same schema with [`@mcp-b/react-webmcp`](/packages/react-webmcp/reference) when you also need
MCP output metadata or formatting. Both hooks use the validator supplied by the schema. See the
[core reference](/packages/usewebmcp/reference#schemas-and-inference) for supported interfaces and types.

If your library supplies only Standard Schema validation, also provide its Standard JSON Schema
converter. Consult the [Standard JSON Schema implementer guide](https://standardschema.dev/json-schema)
for your library's conversion API. Passing a converter-only object supplies metadata but does not
add validation to the hook.

## Infer input from a JSON Schema literal

Pass an inline JSON Schema object to either hook. The hook preserves literal types without `as const`.
For a reusable schema constant, use `as const` to keep its literal information. Validate in your
handler when using plain JSON Schema; hook input inference does not perform runtime validation.

For direct browser registration, activate the Community Group's declarations:

```bash title="Install browser declarations"
pnpm add -D webmcp-types
```

Import `type { WebMCP }` from `webmcp-types` when naming browser contracts. Use
[`@mcp-b/webmcp-types`](/packages/webmcp-types/reference) for MCP-B descriptor helpers and
compatibility types. Both packages can be loaded together.

## Validate callbacks outside React

Install [`@mcp-b/webmcp-plugins`](https://github.com/WebMCP-org/npm-packages/tree/main/packages/webmcp-plugins)
and your schema library. Provide native WebMCP or initialize the polyfill separately.

```bash title="Install the adapter and Zod"
pnpm add @mcp-b/webmcp-plugins zod@^4.2
```

```ts title="total-tool.ts"
import { createInvocationCallback } from '@mcp-b/webmcp-plugins';
import { standardSchema } from '@mcp-b/webmcp-plugins/standard-schema';
import { z } from 'zod';

const input = standardSchema(
  z.object({
    count: z.string().regex(/^\d+$/).transform(Number),
    limit: z.number().default(10),
  })
);

export async function registerTotalTool() {
  const context = document.modelContext;
  if (!context) throw new Error('Initialize WebMCP before registering tools');
  const registration = new AbortController();
  const tool = { instanceId: crypto.randomUUID(), name: 'calculate_total' };

  await context.registerTool(
    {
      name: tool.name,
      description: 'Add a numeric count to a limit, which defaults to 10',
      inputSchema: input.inputSchema,
      execute: createInvocationCallback(() => ({
        tool,
        input,
        signal: registration.signal,
        execute: ({ count, limit }) => ({ total: count + limit }),
      })),
    },
    { signal: registration.signal }
  );

  return () => registration.abort();
}
```

Call the returned cleanup function when the tool is no longer needed. The adapter projects JSON
metadata and validates/transforms once per call before execution or consent. The MCP bridge
recognizes the managed callback and keeps MCP validation inside the same invocation.
The [plugin reference](https://github.com/WebMCP-org/npm-packages/tree/main/packages/webmcp-plugins#register-a-callback-outside-react)
covers named plugins and local `invoke()` calls.

The standalone polyfill accepts JSON metadata; it does not automatically call vendor validators.
For an unwrapped `BrowserMcpServer` tool, MCP calls use the SDK validator while direct browser
calls bypass it. See the [SDK schema boundary](/packages/webmcp-ts-sdk/reference#schema-boundary).

## Add MCP-B output metadata

Add `outputSchema` when an MCP client needs typed structured data. Declare the descriptor
separately so `ToolDescriptorFromSchema` checks the returned value:

```ts title="search-summary-tool.ts"
import '@mcp-b/global';
import type { JsonSchemaForInference, ToolDescriptorFromSchema } from '@mcp-b/webmcp-types';

const inputSchema = {
  type: 'object',
  properties: {
    query: { type: 'string' },
    limit: { type: 'integer', minimum: 1 },
  },
  required: ['query'],
  additionalProperties: false,
} as const satisfies JsonSchemaForInference;

const outputSchema = {
  type: 'object',
  properties: {
    total: { type: 'integer' },
    items: { type: 'array', items: { type: 'string' } },
  },
  required: ['total'],
  additionalProperties: false,
} as const satisfies JsonSchemaForInference;

const tool = {
  name: 'search_summary',
  description: 'Search with summary',
  inputSchema,
  outputSchema,
  execute: ({ query }) => ({ total: 1, items: [query] }),
} satisfies ToolDescriptorFromSchema<typeof inputSchema, typeof outputSchema>;

const context = document.modelContext;
if (!context) throw new Error('WebMCP is unavailable');
await context.registerTool(tool);
```

`outputSchema` is MCP-B metadata for output inference and structured MCP responses. If your handler
constructs an MCP `CallToolResult` directly, include schema-compatible `structuredContent` as well
as human-readable `content`. The [package reference](/packages/webmcp-types/reference) lists the
output inference types.

`outputSchema` is enforced on calls through the official MCP server. The React hook uses it for
inference and checks JSON serializability, but does not enforce the output schema on local or direct
browser calls. For React, the [MCP-B hook example](/packages/react-webmcp/overview) shows a complete
component with an output schema.

## Check the agent-facing schema

After registration, inspect the emitted schema in Chrome's [WebMCP DevTools
panel](https://developer.chrome.com/docs/devtools/application/webmcp). Then run the [Lighthouse
WebMCP schema validity
audit](https://developer.chrome.com/docs/lighthouse/agentic-browsing/webmcp-schema-validity).

Use Chrome's [WebMCP best
practices](https://developer.chrome.com/docs/ai/webmcp/best-practices) for names, descriptions, and
schema design. Use [WebMCP evals](https://developer.chrome.com/docs/ai/webmcp/evals) to test whether
agents select the tool and supply the expected arguments.
